I'm **Brian Mwenda** — a full-stack developer and founder based in **Nairobi, Kenya 🇰🇪**. #### 🧾 Fahari POS · *Private repository*
> **A multi-tenant, eTIMS-ready point-of-sale and retail management platform**

Each retailer signs up for their own shop and sees only their own data. A separate, walled-off platform admin layer lets me see every shop, suspend or reactivate it, and configure each shop's M-Pesa and eTIMS credentials.

- **Retail operations:** POS checkout (cash, M-Pesa, card), stock ledger, purchasing with partial receiving, supplier management, till sessions with cash reconciliation and Z-reports, discounts, returns and tables/bill-splitting for hospitality
- **Isolation by design:** shop and admin sessions use different secrets and cookies, so one can never be replayed as the other. I verified this in both directions, and verified that suspension takes effect mid-session
- **Credentials handled properly:** per-branch Daraja and eTIMS config, encrypted at rest and never returned to the browser
- **Status:** pre-pilot, with real VSCU eTIMS integration on the roadmap

## 📊 Data & AI Work

### 💰 [WBFET — Web-Based Financial Expenses Tracker](https://github.com/thebrianmwenda/wbfet) · *Public*
> A bilingual (English / Kiswahili) personal-finance PWA with M-Pesa STK Push

Full-stack React, Node.js and PostgreSQL app with Daraja integration, built mobile-first with WCAG AA accessibility. QA coverage includes 80+ test cases, Postman API testing and exploratory testing, and the data layer powers budget-vs-actual reporting and M-Pesa reconciliation.

### 📈 [Kenya Mobile Credit Risk Profiler](https://github.com/thebrianmwenda/kenya-credit-risk-profiler) · *Public*
> Segmenting mobile-borrower risk from behavioural and financial survey data

An end-to-end analytics project on **286 Nairobi CBD respondents**: cleaning and EDA in Pandas, K-Means borrower segmentation, logistic regression and decision-tree risk classification (**82% accuracy**), Seaborn/Matplotlib visualisations, and Stata validation. It is grounded in the Technology Acceptance Model, Theory of Planned Behavior and Behavioral Finance.

```
Raw survey data (n=286) → Cleaning & EDA → K-Means segmentation
   → Logistic Regression + Decision Tree → Dashboards → Stata validation
```
